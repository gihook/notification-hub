Send a notification

curl -X POST {{ endpoint }} \
  -H 'Content-Type: application/json' \
  -d '{"notification_id": "{{ example_id }}", "data": {"any": "json"}}'

Responses: 202 queued · 400 invalid body · 404 unknown notification_id · 503 broker unavailable.

How it works

  1. The hub looks up notification_id in config/routing.json.
  2. For every target it publishes one Celery message to that queue in RabbitMQ.
  3. A Celery worker consuming that queue runs the task with the same name. It gets event_id, notification_id, data and received_at as keyword arguments.
